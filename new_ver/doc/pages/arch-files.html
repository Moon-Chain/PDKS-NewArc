Dosya Çalışma Sırası

Bu sayfa; derleme zamanında esbuild'in hangi dosyadan ne ürettiğini, sunucu başlarken Node.js modüllerinin hangi sırayla yüklendiğini ve tarayıcıda CSS, JS, Service Worker dosyalarının hangi öncelikte işlendiğini detaylandırır.

Sarı — komut / giriş noktası  |  Mavi — dosya / modül  |  Mor — üretilen çıktı  |  Yeşil — koşul / dal  |  Gri — yorum

1 — Derleme Zamanı (build.ts)

tsx build.ts ya da npm run build çalıştırıldığında esbuild iki bağımsız bundle üretir. Code splitting açık olduğundan her sayfa kendi chunk'ına derlenir; ortak kod (Alpine.js, ApiClient vb.) yalnızca ana bundle'da yer alır. 

$ tsx build.ts  ← veya: npm run build:watch (watch mode)
│
├─ ── Kullanıcı Uygulaması ────────────────────────────────────────
│    ├─ Giriş: public/ts/app.ts
│    ├─ esbuild.build({
│    │      format: 'esm', splitting: true, bundle: true,
│    │      outdir: 'public/js/'
│    │  })
│    └─ Üretilen dosyalar:
│         ├─ public/js/app.js              ← ana bundle; Alpine.js, Router, StateManager dahil
│         ├─ public/js/chunks/login-[hash].js
│         ├─ public/js/chunks/home-[hash].js
│         ├─ public/js/chunks/leaves-[hash].js
│         ├─ public/js/chunks/approvals-[hash].js
│         ├─ public/js/chunks/users-[hash].js
│         ├─ public/js/chunks/profile-[hash].js
│         ├─ public/js/chunks/movements-[hash].js
│         ├─ public/js/chunks/qr-[hash].js
│         ├─ public/js/chunks/settings-[hash].js
│         └─ public/js/chunks/notifications-[hash].js
│
├─ ── Admin Paneli ────────────────────────────────────────────────
│    ├─ Giriş: public/admin/ts/app-admin.ts
│    ├─ esbuild.build({ outdir: 'public/admin/js/' })
│    └─ Üretilen dosyalar:
│         ├─ public/admin/js/app-admin.js      ← admin ana bundle
│         ├─ public/admin/js/chunks/dashboard-[hash].js
│         ├─ public/admin/js/chunks/users-[hash].js
│         ├─ public/admin/js/chunks/movements-[hash].js
│         └─ ... (her admin sayfası için chunk)
│
├─ ── Service Worker versiyonu güncellendi ────────────────────────
│    ├─ Derleme çıktısının hash'i hesaplandı
│    └─ public/sw.js içindeki CACHE_VERSION sabiti yeni hash ile değiştirildi
│         Böylece yeni deploy'da eski cache geçersiz kalır
│
└─ ✓ Derleme tamamlandı  (watch modunda: dosya değişiminde tekrar tetiklenir)

2 — Sunucu Modül Yükleme Sırası

Node.js, import ifadelerini derinlik öncelikli (depth-first) olarak çözümler. Aşağıdaki sıra, server.ts'nin en üst satırından app.listen()'e kadar modüllerin belleğe alınma düzenini gösterir.

# Dosya Ne Yapar? Bağımlılıkları
1 dotenv .env dosyasını process.env'e yükler —
2 core/Logger.ts Winston singleton oluşturur, dosya + konsol transport winston, winston-daily-rotate-file
3 middleware/requestId.ts Her isteğe UUID ekleyen middleware factory uuid
4 middleware/rateLimit.ts globalLimiter oluşturur (100 istek / 15 dk) express-rate-limit
5 core/AppError.ts Özel hata sınıfı tanımlar —
6 db/connection.ts pg.Pool oluşturur (henüz bağlantı yok — lazy) pg
7 core/BaseRepository.ts Soyut repository sınıfı (SQL yardımcıları) db/connection
8 repositories/*.ts Her entity için somut repository sınıfları BaseRepository
9 core/BaseService.ts Soyut servis sınıfı (yetki yardımcıları) AppError
10 services/*.ts Her domain için iş mantığı servisleri BaseService + ilgili Repo'lar
11 routes/v1/*.ts Express Router'ları (handler'lar servisleri çağırır) ilgili Service'ler
12 events/emitter.ts EventEmitter singleton node:events
13 events/setup.ts emitter.on() çağrılarını kaydeder emitter, NotificationService, Logger
14 server.ts (devam) Middleware + route bağlama + listen() yukarıdaki hepsi

3 — Tarayıcıda Dosya Yükleme Sırası

Tarayıcı index.html'yi parse ettiğinde dosyalar belirli bir öncelik sırasıyla yüklenir. Aşağıdaki ağaç bu sırayı ve her dosyanın tarayıcı üzerindeki etkisini gösterir. 

Tarayıcı index.html'yi parse etmeye başladı
│
├─ [1] css/components.css  ← render-blocking; indirilene kadar First Paint olmaz
│        Buton, form, kart, modal stilleri yüklendi
│
├─ [2] css/style.css  ← render-blocking
│        CSS değişkenleri (--color-*, --radius, vb.)
│        Dark theme desteği yüklendi
│
├─ [3] manifest.json  ← arka planda; render'ı engellemez
│        PWA kurulum bilgisi (app_name, icons, start_url)
│
├─ [4] ── HTML body parse tamamlandı ──────────────────────────────
│        3 boş container DOM'da: #header-container, #app, #nav-container
│        ↳ İlk görüntü: tamamen boş, yükleniyor gibi
│
├─ [5] js/app.js  ← defer; HTML parse bitince yüklenir, render'ı engellemez
│        ├─ Alpine.js (app.js içinde bundle'lı)
│        ├─ Router, StateManager, ApiClient, EventStream
│        ├─ TopBar ve BottomNav component class'ları
│        └─ Sayfa class'ları (LoginPage, HomePage...) HENÜZ değil — lazy chunk'lar
│
├─ [6] app.js çalıştı → init() tetiklendi
│        ├─ api.get('/api/v1/auth/me')  → ağ isteği
│        └─ Yanıt bekleniyor...
│
├─ [7] Oturum yanıtı geldi → router._render('/home')
│        └─ import('./pages/HomePage.js')  → dinamik import
│             └─ js/chunks/home-[hash].js  ağdan indirildi
│                  İlk ziyarette ağdan; sonraki ziyaretlerde SW cache'inden
│
├─ [8] HomePage render edildi → ekran dolu
│        ↳ ✓ İlk Anlamlı İçerik (FCP)
│
└─ [9] sw.js  ← arka planda; render'dan sonra kaydedilir
         ├─ İlk ziyaret: install event → cache oluşturuldu
         │    ├─ CSS, JS bundle'lar, ikonlar → CacheFirst
         │    └─ /offline.html → fallback olarak cache'e alındı
         └─ Sonraki ziyaretler: activate event → eski cache temizlendi

4 — Sayfa Chunk'ı Akışı (lazy import)

Kullanıcı hiçbir zaman /leaves sayfasına gitmemişse, leaves-[hash].js dosyası asla indirilmez. İlk kez /leaves'e gidildiğinde şu akış gerçekleşir: 

Kullanıcı ilk kez /leaves sayfasına geçti
│
├─ router._render('/leaves')  → routes['/leaves']()
│    └─ import('./pages/LeavesPage.js')  → dinamik import
│
├─ ── Tarayıcı ağ isteği gönderdi ─────────────────────────────────
│    ├─ SW intercept etti: js/chunks/leaves-[hash].js
│    ├─ [SW cache'de yok — ilk kez]
│    │    ├─ Ağdan indirildi
│    │    ├─ Cache'e kaydedildi
│    │    └─ Tarayıcıya döndürüldü
│    └─ [SW cache'de var — sonraki ziyaret]
│         └─ Doğrudan cache'den döndürüldü  (ağa çıkılmadı)
│
├─ LeavesPage class parse edildi & bellekte hazır
├─ new LeavesPage(container).render()  → sayfa DOM'a yazıldı
└─ ✓ LeavesPage ekranda  (sonraki gidişlerde SW'dan anında gelir)
Dosya adlarındaki [hash] kısmı esbuild tarafından dosya içeriğine göre otomatik hesaplanır. Kod değiştiğinde hash değişir → SW eski cache'i siler → tarayıcı yeni dosyayı indirir. Değişmeyen chunk'lar cache'de aynen kalır → gereksiz indirme olmaz.

5 — Service Worker Dosya Akışı

sw.js ilk kez kaydedildi (navigator.serviceWorker.register)
│
├─ ── install event ───────────────────────────────────────────────
│    ├─ CACHE_VERSION sabiti: 'pdks-v[hash]'
│    ├─ Cache.addAll([])  → önceden belirtilen statik dosyalar cache'e alındı
│    │    ├─ /offline.html
│    │    ├─ /css/style.css
│    │    ├─ /css/components.css
│    │    └─ /icons/*.png
│    └─ self.skipWaiting()  → anında aktif ol
│
├─ ── activate event ──────────────────────────────────────────────
│    ├─ Eski cache'ler silindi  (CACHE_VERSION eşleşmeyenler)
│    └─ clients.claim()  → açık sekmelerin kontrolünü al
│
└─ ── fetch event (her ağ isteğinde) ──────────────────────────────
     ├─ [/api/* isteği]  → NetworkFirst
     │    ├─ Ağdan dene → başarıysa döndür, cache'e kaydet
     │    └─ [ağ yoksa]  → cache'den döndür
     ├─ [JS/CSS/İkon isteği]  → CacheFirst
     │    ├─ Cache'de varsa anında döndür
     │    └─ [cache'de yoksa]  → ağdan indir, cache'e kaydet
     └─ [HTML sayfası isteği (navigate)]  → NetworkFirst
          ├─ Ağdan dene
          └─ [ağ yoksa]  → /offline.html fallback döndür
