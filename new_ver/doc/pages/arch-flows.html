Kullanıcı Eylem Akışları

Bu sayfa; gerçek kullanıcı eylemlerinin istemciden başlayıp veritabanına ulaşana kadar geçtiği tam dallanma yolunu gösterir. Her hata yolu, her koşul dalı ve her yan etki (event, bildirim, SSE) dahil edilmiştir.

Sarı/Kalın — kullanıcı eylemi  |  Mavi — fonksiyon/metod  |  Turuncu — event emit  |  Altın — SQL / veritabanı  |  Açık mavi — HTTP isteği  |  Yeşil — koşul/dal  |  Kırmızı — hata/red  |  Parlak yeşil — başarı

1 — Giriş Yapma (Login)

Kullanıcı login formunu doldurup "Giriş Yap"a tıkladı
│
├─ ── İstemci tarafı ──────────────────────────────────────────────
│    ├─ LoginPage.handleSubmit()  tetiklendi
│    ├─ email + password form verisi toplandı
│    ├─ [alan boşsa]  → hata mesajı göster, istek gönderme
│    └─ api.post('/api/v1/auth/login', {email, password})
│         fetch() — credentials: 'include' (cookie için)
│
├─ ── Sunucu — Middleware zinciri ─────────────────────────────────
│    ├─ requestId  → req.requestId = UUID
│    ├─ globalLimiter  → IP bazlı istek sayısı kontrol
│    │    └─ [limit aşıldı]  → 429 Too Many Requests
│    └─ validate(loginSchema)  → body kontrol
│         └─ [eksik alan / geçersiz email]  → 400 Bad Request
│
├─ ── Route Handler: POST /api/v1/auth/login ──────────────────────
│    └─ AuthService.login(email, password)
│         ├─ UserRepository.findByEmail(email, companyId)
│         │    └─ SELECT id, password_hash, role, is_active FROM users WHERE email=$1
│         │         └─ [kullanıcı bulunamadı]  → throw AppError(401, 'Geçersiz kimlik bilgileri')
│         ├─ bcrypt.compare(password, user.password_hash)
│         │    └─ [eşleşmedi]  → throw AppError(401, 'Geçersiz kimlik bilgileri')
│         ├─ [user.is_active === false]  → throw AppError(403, 'Hesap devre dışı')
│         ├─ jwt.sign({id, role, company_id, jti}, JWT_SECRET, {expiresIn:'7d'})
│         ├─ AuditRepository.log({actor: user.id, action: 'login', ip})
│         │    └─ INSERT INTO audit_log (...) VALUES (...)
│         └─ return {user, token}
│
├─ ── HTTP Yanıtı ─────────────────────────────────────────────────
│    ├─ res.cookie('pdks_token', token, {httpOnly: true, secure, sameSite:'lax'})
│    └─ res.json(200, {user, message: 'Giriş başarılı'})
│
└─ ── İstemci — Yanıt işlendi ─────────────────────────────────────
     ├─ state.set('user',    {id, role, company_id})
     ├─ state.set('profile', profile)
     ├─ state.watch('user') tetiklendi:
     │    ├─ renderTopBar()  → TopBar mount edildi
     │    ├─ renderNav()     → BottomNav mount edildi
     │    └─ eventStream.connect()  → SSE bağlantısı açıldı
     └─ router.navigate('/home')  → ✓ Ana sayfa açıldı

2 — QR ile Giriş/Çıkış Kaydı

Kullanıcı Ana Sayfa'da "QR Tara" butonuna tıkladı
│
├─ new QRScanner().open(onSuccess)
│    ├─ navigator.mediaDevices.getUserMedia({video: true})
│    │    └─ [izin reddedildi]  → hata toast: Kamera izni gerekli
│    ├─ <video> elementi DOM'a eklendi, stream bağlandı
│    └─ requestAnimationFrame döngüsü başladı:
│         ├─ canvas.drawImage(video frame)
│         ├─ jsQR(imageData)  → QR kodu algılandı mı?
│         │    └─ [algılandı]  → qrValue alındı, stream durduruldu
│         └─ [algılanmadı]  → döngü devam eder
│
├─ ── QR değeri alındı, işleniyor ─────────────────────────────────
│
├─ [çevrimdışı]  → offline queue akışı
│    ├─ IndexedDB'ye kayıt: {type, qrValue, timestamp}
│    ├─ Toast: "Kayıt offline tutuldu, internete bağlanınca gönderilecek"
│    └─ → bkz. Bölüm 5: Offline → Online Sync
│
└─ [çevrimiçi]
     ├─ api.post('/api/v1/attendance', {qrValue, type: 'in'})
     │
     ├─ ── Sunucu — Middleware ─────────────────────────────────────────
     │    ├─ auth  → cookie decode → req.user set
     │    │    └─ [token yoksa / geçersizse]  → 401 Unauthorized
     │    └─ validate  → qrValue zorunlu
     │
     ├─ ── Route Handler: POST /api/v1/attendance ──────────────────────
     │    └─ AttendanceService.checkIn({userId, companyId, qrValue, type})
     │         ├─ SettingsRepository.get(companyId)
     │         │    └─ SELECT qr_secret, work_start, work_end FROM settings WHERE company_id=$1
     │         ├─ [qrValue !== settings.qr_secret]  → throw AppError(400, 'Geçersiz QR kodu')
     │         ├─ AttendanceRepository.getLastRecord(userId, today)
     │         │    └─ SELECT * FROM attendance_logs WHERE user_id=$1 ORDER BY created_at DESC LIMIT 1
     │         ├─ [son kayıt type='in' ve 30 saniye içindeyse]  → throw AppError(409, 'Çok hızlı')
     │         ├─ [son kayıt type='in']  → yeni kayıt type='out' olacak
     │         ├─ [son kayıt type='out' veya yok]  → yeni kayıt type='in'
     │         ├─ AttendanceRepository.create({userId, companyId, type, timestamp})
     │         │    └─ INSERT INTO attendance_logs (user_id, company_id, type, timestamp) VALUES (...)
     │         ├─ emitter.emit('attendance:checkin', {userId, companyId, type, timestamp})
     │         │    └─ SSE Manager → bağlı admin client'larına anlık bildirim
     │         └─ return {record, message}
     │
     └─ ── İstemci ─────────────────────────────────────────────────────
          ├─ Toast: "Giriş kaydedildi / Çıkış kaydedildi"
          └─ HomePage'in durum kartı yenilendi

3 — İzin Talebi Oluşturma

Kullanıcı İzinler sayfasında "İzin Talep Et" butonuna tıkladı
│
├─ LeavesPage.openNewLeaveModal()
│    └─ new Modal().open('İzin Talebi', formHTML, onSubmit)
│
├─ Kullanıcı formu doldurup "Gönder"e tıkladı
│    ├─ startDate, endDate, type, reason form verisi toplandı
│    ├─ [tarihler geçersiz / boşsa]  → form hataları göster
│    └─ api.post('/api/v1/leaves', {startDate, endDate, type, reason})
│
├─ ── Sunucu — Middleware ─────────────────────────────────────────
│    ├─ auth  → req.user set
│    └─ validate  → tarih zorunlu, type enum'a uygun mu
│
├─ ── Route Handler: POST /api/v1/leaves ──────────────────────────
│    └─ LeaveService.create({userId, companyId, startDate, endDate, type, reason})
│         ├─ HolidayRepository.getByYear(year, companyId)
│         │    └─ SELECT date FROM holidays WHERE company_id=$1 AND year=$2
│         ├─ İş günü hesabı: startDate → endDate arası hafta sonu + tatil çıkarıldı
│         │    └─ businessDays = toplam iş günü
│         ├─ LeaveRepository.getBalance(userId, year)
│         │    └─ SELECT used_days, total_days FROM leave_balances WHERE user_id=$1 AND year=$2
│         ├─ [kalan bakiye < businessDays]  → throw AppError(400, 'Yetersiz izin bakiyesi')
│         ├─ LeaveRepository.create({...data, businessDays, status: 'pending'})
│         │    └─ INSERT INTO leaves (user_id, company_id, start_date, end_date, type, days, status) VALUES (...)
│         ├─ Yönetici bulundu: UserRepository.findManager(companyId)
│         └─ emitter.emit('leave:requested', {companyId, managerId, userId, userName, leaveId, days, type})
│              └─ events/setup.ts listener:
│                   └─ NotificationService.notify({userId: managerId, title: 'Yeni İzin Talebi', ...})
│                        ├─ NotificationRepository.create({...})
│                        │    └─ INSERT INTO notifications (...)
│                        ├─ [yönetici SSE bağlıysa]  → SSE akışı: anlık bildirim
│                        └─ [yönetici push aboneyse]  → webPush.sendNotification()
│
└─ ── İstemci ─────────────────────────────────────────────────────
     ├─ Toast: "İzin talebiniz gönderildi"
     └─ İzin listesi yenilendi  → api.get('/api/v1/leaves')

4 — İzin Onayı (Yönetici)

Yönetici Onaylar sayfasında "Onayla" butonuna tıkladı
│
├─ ApprovalsPage.approve(leaveId, 'leave')
│    └─ api.post('/api/v1/leaves/{id}/approve')
│
├─ ── Sunucu — Middleware ─────────────────────────────────────────
│    ├─ auth  → req.user set
│    ├─ roles(['admin', 'mudur'])  → yetki kontrol
│    │    └─ [role 'personel' ise]  → 403 Forbidden
│    └─ validate  → leaveId path param
│
├─ ── Route Handler: POST /api/v1/leaves/:id/approve ──────────────
│    └─ LeaveService.approve(leaveId, approverId, companyId)
│         ├─ LeaveRepository.findById(leaveId, companyId)
│         │    └─ [bulunamadı]  → throw AppError(404, 'İzin bulunamadı')
│         ├─ [leave.status !== 'pending']  → throw AppError(400, 'Bu talep zaten işleme alınmış')
│         ├─ LeaveRepository.update(leaveId, {status: 'approved', approved_by: approverId, approved_at: now})
│         │    └─ UPDATE leaves SET status='approved', approved_by=$2 WHERE id=$1
│         ├─ emitter.emit('leave:approved', {companyId, userId: leave.user_id, approverName, leaveId, days})
│         │    └─ events/setup.ts listener:
│         │         └─ NotificationService.notify({userId: personel, title: 'İzin Onaylandı', type:'success'})
│         │              ├─ INSERT INTO notifications (...)
│         │              ├─ [personel SSE bağlıysa]  → anlık bildirim
│         │              └─ [personel push aboneyse]  → tarayıcı bildirimi
│         └─ AuditRepository.log({actor: approverId, action: 'leave_approved', target: leaveId})
│              └─ INSERT INTO audit_log (...)
│
└─ ── İstemci ─────────────────────────────────────────────────────
     ├─ Toast: "İzin onaylandı"
     └─ Onay listesi yenilendi  → bekleyen talep listeden kalktı

── Paralel: Personelin tarafında ───────────────────────────────────
[personel aynı anda uygulamadaysa → SSE üzerinden]
└─ EventSource mesajı alındı: {type: 'notification', data: {title: 'İzin Onaylandı'}}
     ├─ NotificationPanel  → zil ikonunda kırmızı nokta belirdi
     └─ Toast.show('İzin talebiniz onaylandı', 'success')  → ekranda gösterildi

5 — Offline → Online Senkronizasyon

Kullanıcı internet yokken QR kodu taradı
│
├─ api.post('/api/v1/attendance', ...)  → ağ isteği başarısız
│    └─ offline.ts: addToQueue({type, qrValue, timestamp})
│         └─ IndexedDB  → kayıt eklendi
│              store: 'offline_queue'
│              key: auto-increment id
│
├─ Toast: "Offline kayıt tutuldu, internete bağlanınca gönderilecek"
│
│
Kullanıcı internete bağlandı
│
├─ [Yol 1: window 'online' event]
│    └─ window.addEventListener('online', syncQueue)  tetiklendi
│         └─ syncQueue(sendOfflineItem)  çağrıldı
│
├─ [Yol 2: Service Worker Background Sync (tarayıcı destekliyorsa)]
│    └─ SW 'sync' event  → listenSWSync(sendOfflineItem)  tetiklendi
│
└─ ── Senkronizasyon döngüsü ──────────────────────────────────────
     ├─ IndexedDB'deki tüm offline_queue kayıtları okundu
     └─ Her kayıt için:
          ├─ sendOfflineItem({type, qrValue, timestamp})
          │    └─ api.post('/api/v1/attendance', {..., isOffline: true})
          │         ├─ [200 başarılı]
          │         │    ├─ IndexedDB'den kayıt silindi
          │         │    └─ Toast: "Offline kayıt senkronize edildi"
          │         └─ [hata — 409 Conflict vs.]
          │              ├─ Kayıt sırada kalır
          │              └─ Sonraki online olunca tekrar denenecek
          └─ Tüm kayıtlar işlenene kadar devam edildi

6 — SSE Gerçek Zamanlı Bağlantı

Kullanıcı giriş yaptı → eventStream.connect() çağrıldı
│
├─ new EventSource('/api/v1/events')
│    └─ Tarayıcı kalıcı HTTP bağlantısı açtı
│
├─ ── Sunucu: GET /api/v1/events ──────────────────────────────────
│    ├─ auth middleware  → req.user set
│    ├─ res.setHeader('Content-Type', 'text/event-stream')
│    ├─ res.setHeader('Cache-Control', 'no-cache')
│    ├─ sseClients.set(userId, res)  → client Map'e eklendi
│    └─ İstemci bağlı kaldıkça bağlantı açık:
│         Her 30 saniyede: res.write(':ping\n\n')  → heartbeat
│
├─ ── Olay tetiklenince (örn. izin onayı) ─────────────────────────
│    └─ NotificationService.notify({userId, ...})
│         ├─ [userId SSE bağlıysa]  → sseClients.get(userId)
│         └─ res.write(`event: notification\ndata: ${JSON.stringify(payload)}\n\n`)
│
├─ ── İstemci: EventSource mesajı aldı ────────────────────────────
│    └─ EventStream.on('notification', handler)  tetiklendi
│         ├─ NotificationPanel  güncellendi (zil ikonu)
│         └─ Toast.show(payload.title, 'info')
│
└─ ── Bağlantı kopunca ────────────────────────────────────────────
     ├─ [kullanıcı çıkış yaptı]  → eventStream.disconnect()
     │    └─ EventSource.close() → sunucu req.on('close') tetiklenir
     │         └─ sseClients.delete(userId)
     └─ [ağ hatası / tarayıcı sekmesi kapandı]
          └─ EventSource otomatik yeniden bağlanmayı dener (browser built-in)

7 — Excel Raporu İndirme

Admin "Rapor İndir" butonuna tıkladı
│
├─ ReportsPage.downloadReport(type, from, to)
│    └─ api.get('/api/v1/reports/attendance?from=...&to=...', {responseType: 'blob'})
│
├─ ── Sunucu ──────────────────────────────────────────────────────
│    ├─ auth + roles(['admin'])  → yetki kontrol
│    └─ ExcelService.generateAttendanceReport(companyId, from, to)
│         ├─ AttendanceRepository.getByDateRange(companyId, from, to)
│         │    └─ SELECT u.name, a.type, a.timestamp FROM attendance_logs a JOIN users u...
│         ├─ new ExcelJS.Workbook()  → çalışma kitabı oluşturuldu
│         ├─ Başlık satırı + veri satırları eklendi
│         ├─ Stil uygulandı (kolon genişlikleri, bold başlık)
│         ├─ workbook.xlsx.writeBuffer()  → Buffer üretildi
│         └─ return buffer
│    ├─ res.setHeader('Content-Type', 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet')
│    └─ res.setHeader('Content-Disposition', 'attachment; filename="devam_raporu.xlsx"')
│
└─ ── İstemci ─────────────────────────────────────────────────────
     ├─ Blob alındı
     ├─ URL.createObjectURL(blob)  → geçici URL oluşturuldu
     ├─ <a href="..." download="...">  → tıklatıldı, indirme başladı
     └─ ✓ .xlsx dosyası indirildi
Her kullanıcı eylemi şu zinciri izler: İstemci UI → ApiClient.fetch() → Middleware (auth + rate limit + validate) → Route Handler → Service (iş mantığı) → Repository (SQL) → PostgreSQL. Yan etkiler (bildirim, SSE, audit log) ise EventEmitter üzerinden servis katmanından ayrılmış biçimde çalışır.
